# Library Packages

1. Use `bunup` or `tsdown` for bundling libraries
2. Define clear public APIs with exports
3. Use `main` and `types` fields in package.json
4. Provide both ESM and CJS builds when needed
5. Generate type declarations automatically
6. Use semantic versioning for releases
7. Document public APIs with JSDoc comments
8. Keep libraries framework-agnostic when possible
9. Use peer dependencies for optional integrations
10. Test libraries with unit tests
11. Provide examples in README
12. Use `exports` field for conditional exports
13. Use `files` field to control published files
14. Set `publishConfig.access` to `public` for open source
15. Use `auto-it` for automated releases
